# 队友交接指南：听觉账单手工书

项目英文名：**The Listening Ledger**  
适用版本：v0.4.0；编写日期：2026 年 11 月 12 日（北京时间）。  
本文帮助队友理解产品、在自己的电脑启动、核对已有成果，并配合录屏。仓库、视频和 Devpost 的发布状态须以实际链接和提交回执为准；本文件本身不是提交成功证明。

## 1. 先用一分钟理解我们在做什么

这是一款**把消费记录变成可翻阅、可聆听手账的本地网页应用**。用户打开一本书，地图沿着消费节点生长；不同音型提醒“预算内”“需要关注”“待核对”。想知道具体金额和原因时，再点击节点查看文字或朗读。

我们希望服务不愿经常翻表格、但愿意通过较轻松方式回顾支出的人。这是目前的目标用户假设，尚未通过正式用户研究证明“所有人更高效”或“能降低焦虑”。

一句话介绍可以这样说：

> 把账单变成一本可以听的手账：先听见需要关注的地方，再看清依据，最后由自己确认。

产品的关键不是音乐装饰，而是这条流程：

**打开账本 → 听见状态差异 → 点开具体消费 → 理解提醒原因 → AI 辅助分类 → 人工确认 → 预算与地图更新 → 留下历史。**

它不评价消费是否道德，不认证商户安全，不判断诈骗，不替用户付款或退款，也不提供投资建议。

## 2. 两本书、三种声音、三种分工

### 两本书是同一批消费的两种阅读方式

| 入口 | 用来回答什么问题 | 如何看 |
| --- | --- | --- |
| 日期手记 / Daily Journal | 我这段时间怎样花钱？ | 按日期翻页，观察一天内的消费节点与节奏 |
| 生活图鉴 / Spending Collection | 钱花在哪些生活类别？ | 按消费分类翻阅，如教育、餐饮、购物 |
| 账单索引 | 我想直接找到某一笔 | 直接打开记录，不必等动画或逐页寻找 |

切换书的类型不会复制消费，也不会创建第二笔交易。两种书体、页面编排和主题有所区别；页面插画依据已确认内容选择现有素材。

### 三种声音只表示当前核对状态

| 状态 | 音型 | 正确含义 | 不能这样讲 |
| --- | --- | --- | --- |
| 绿色圆形：预算内 | 暖和弦，连贯、柔和 | 在已知数据与适用规则下，没有未解决事项或提醒触发 | “这是好消费／安全商户” |
| 红色带边角：需要关注 | 木敲提醒，两组短打 | 超过明确设置的限额，或命中用户提醒 | “坏消费／骗子商户” |
| 蓝色问号：待核对 | 玻璃问句，留白后上行 | 分类、消费识别或可判断的数据仍不足 | “已经发现异常／已经超支” |

如果一笔既需要核对，又有确定的超额事实，主状态可以保持蓝色，详情仍说明超额；不要把颜色当成唯一事实。声音旁同时有文字和形状，静音也能使用。

### 程序、AI、PayPal 分别做什么

| 部分 | 实际职责 | 用户在哪里检查 |
| --- | --- | --- |
| 确定的程序规则 | 用整数分计算金额、预算和状态；保存历史；判断哪些交易可展示 | 详情里的金额、预算周期、累计、原因与限额版本 |
| DeepSeek AI | 根据商户说明和用户补充用途，建议分类并引用输入依据；回顾时选择程序提供的事实重点 | “帮我弄清这笔”中的发送预览、建议、引用；回顾的来源标记 |
| 用户 | 决定是否采纳分类、是否认识这笔消费、是否仍需核对，以及预算多少 | 分类采纳与“我认识这笔消费”分开操作 |
| PayPal Sandbox | 从已授权账户查询真实沙箱交易，提供来源、状态、金额与同步信息 | “账本来源”和详情中的“PayPal 沙箱交易来源” |

AI 不决定金额，也不会因为它建议“教育”就替用户勾选“我认识这笔消费”。“引用原话确实存在”不代表模型判断一定正确。

**节点音效由浏览器合成；金额朗读使用浏览器／操作系统音色，不是 DeepSeek 生成的语音。** 不要在路演里混为一谈。

## 3. 收到压缩包后，先分清什么能公开

你可能收到的是开发工作目录的完整压缩包，而不是已经排除私密文件的公开源码包。可以在获授权的本机协作使用，但**不要把整个文件夹直接拖进 GitHub、公共网盘或视频素材目录**。

| 文件／目录 | 用途与处理 |
| --- | --- |
| `.env` | 应用的本地服务端配置，可能含模型与 PayPal 密钥；不公开、不截图、不贴聊天 |
| `.env.judging` | 团队准备的独立评审配置；应用不会自动读取这个文件。应由负责人按评审说明安排，不能当作公开示例文件 |
| `.env.sandbox-checkout` | 早前第二商家账户的购买联调配置；正常看账本不需要它，也不需要重新创建购买 |
| `data/`，特别是 `ledger.sqlite` | 本地数据库，可能含账户交易、核对历史与预算；不放公开仓库 |
| `server.log`、`server-error.log`、本地验收证据、账户截图 | 先审查是否含个人或账户信息；不要随源码一并公开 |
| `_release/` | 可能同时有公开候选包和私密评审运行副本，不能整个上传 |
| `.env.example` | 空值／说明模板，可以随公开源码提供；不是可用密钥 |
| 源码、公开文档、授权素材、许可证 | 使用经审查的源码包发布；素材仍需保留各自署名与许可 |

不要通过删除原项目的 `.env` 或数据库来“清理发布”。保留工作目录，另外使用经审查的干净发布包。自己的本地修改需要备份时，先停止服务，再复制到非公开位置。

## 4. Windows 从解压到启动

### 第一步：完整解压

不要在压缩包预览窗口里直接运行。解压后进入同时包含 `server.mjs`、`package.json`、`public` 和 `docs` 的目录。保留 `public/assets` 与 `public/vendor`，不要只发 HTML 文件。

### 第二步：安装并检查 Node.js

需要 **Node.js 22.13.0 或更高版本**。项目使用 Node 内置 SQLite；过低版本可能启动失败。安装来源使用 [Node.js 官方网站](https://nodejs.org/)。

安装后重新打开 PowerShell，输入：

```powershell
node --version
```

应显示 `v22.13.0` 或更高版本。本项目没有需要额外安装的 npm 依赖，正常启动不需要先执行 `npm install`。

### 第三步：首次建议用命令行启动

在文件管理器中打开含 `server.mjs` 的解压目录，在地址栏输入 `powershell` 并回车。这样终端会直接进入正确目录，随后输入：

```powershell
node server.mjs
```

保留这个终端窗口，浏览器打开：

**http://localhost:4333/**

若配置了不同 `PORT`，以服务输出及实际配置为准。浏览器必须通过本地服务访问，不是双击 `public/index.html`。

首次启动会建立本机数据库。终端里按 `Ctrl+C` 停止服务；再运行同一命令会使用已保存的数据。重新打开后如果看不到原记录，先检查是不是启动了另一个解压目录或切换了账本来源，不要立即重置数据库。

### 另一种启动方式

默认端口 4333 下可以双击 `start.cmd`。启动器会检查已有服务，必要时在后台启动，并打开浏览器。关闭网页不等于停止后台服务。

首次排查、修改配置后重启、录制恢复流程时，推荐使用前述命令行方式，便于看见状态并用 `Ctrl+C` 停止。不要为关闭一个项目而结束电脑上的所有 Node 进程。

### 浏览器与地址保持一致

推荐先用当前电脑的 Chrome 或 Edge。`localhost`、`127.0.0.1`、不同端口和不同浏览器可能拥有不同的本地阅读偏好；演示时保持同一地址。`localhost` 只能访问自己电脑的服务，把这个地址发给别人不会让对方连到你的账本。

## 5. 没有密钥，也能先把体验走完

干净源码包不含真实凭据。无密钥启动仍可体验七笔虚构消费、书体翻页、地图、状态音、预算、人工核对与本机保存。

建议第一次按这条路线，约留出 10—15 分钟熟悉操作，不作为运行速度承诺：

1. 查看“账本来源”，选择示例／AI 练习副本。确认当前不是 PayPal 沙箱账本。
2. 先试听图例中的暖和弦、木敲、玻璃问句。使用舒适的系统音量，再调应用音量。
3. 打开“日期手记”，点击开始翻开书，观察路径生长及节点音型。
4. 点击一个节点，阅读金额、状态和提醒原因；需要时展开“听一听这笔 · 设备朗读”。
5. 用“账单索引”找到 `DEMO*042`、金额 ¥20 的练习记录。初始样例用于练习“用途不清 → 补充 → 核对”。若现有副本已核对过，应看到已有状态，不能假定每次打开都是初始状态。
6. 无模型配置时直接使用人工分类和核对；不要把人工操作或规则提示讲成真实 AI 结果。
7. 在“我的限额”查看周期和预算，先预览变化，再决定保存或取消。
8. 切换“生活图鉴”，查看相同消费如何按类别组织。重新打开页面，核对保存是否还在。

示例标准数据为七笔、共 CNY 320；它们是虚构材料，不是 PayPal 同步出来的记录。重置示例会清除该示例的核对、限额及阅读进度，录屏前先确认是否需要保留，不要随手重置。

## 6. 怎样启用真实 AI 和 PayPal 查询

如果收到的包已有可用 `.env`，**不要拿模板覆盖它**。若没有配置，由项目负责人通过非公开方式提供获授权配置，或使用自己的服务账户；不要让队友把密钥发到群里。

配置模板为根目录 `.env.example`。只在 `.env` 尚不存在时，复制模板并改名为 `.env`。Windows 需注意不要存成 `.env.txt`。

| 配置项 | 用途 |
| --- | --- |
| `AI_BASE_URL` | 兼容接口地址；当前项目使用 DeepSeek |
| `AI_MODEL` | 账户可用模型名；现有实测为 `deepseek-flash` |
| `AI_API_KEY` | 模型密钥，只留在服务端 |
| `AI_DAILY_LIMIT` | 每个 UTC 日的请求次数限制；不是费用上限 |
| `PAYPAL_CLIENT_ID`、`PAYPAL_CLIENT_SECRET` | 已开通交易查询权限的 Sandbox 应用凭据 |
| `PORT` | 默认 4333；使用启动器时保留默认值较方便 |

修改后需要停止并重新启动服务。`.env.judging` 不会自动覆盖 `.env`，不要通过更换文件名把团队日常配置弄丢。评审专用配置的交付由负责人安排，见 [评委访问说明](JUDGING_ACCESS.md)。

真实模式的检查顺序：

1. 先到“账本来源”检查配置／连接状态。
2. 对 PayPal，认证成功不等于 Transaction Search 可用；实际同步成功才是交易查询能力的证据。403 不能用示例记录顶替。
3. 对 AI，打开一笔记录的“帮我弄清这笔”，写用途，检查发送预览，确认后发起请求。
4. 区分界面里的真实模型结果、缓存、历史建议和规则摘要。重新打开同一份建议不一定又调用了模型。

真实模型调用可能产生费用，不要为了练熟按钮不断修改输入触发新请求。页面翻动、状态音、手工改分类和设备朗读不调用 DeepSeek。不同电脑的可用设备音色与自然度可能不同。

## 7. 现有 USD 12 沙箱购买怎么核对：不再付款

团队已经有一笔 **USD 12.00 的已完成 Sandbox 购买**。此前完整链路已经实测通过：真实 AI 建议 → 人工确认 → 再同步 → 服务重启与页面重开。这里“真实”指实际调用沙箱与模型接口，不是真实资金消费。

**不需要打开购买辅助页、不需要创建订单，也不需要再支付 USD 12。**

### A. 收到的是已有数据库的工作副本

1. 进入 PayPal 沙箱账本，检查最近同步信息；通过账单索引找到 USD 12 记录。
2. 查看“原始信息与核对历史”：已核对版本应保留“采纳 AI 建议”和独立的“人工确认”。采纳分类后才单独确认认识这笔，不应被合并成“AI 自动确认”。
3. 当前人工分类应为教育；PayPal 原始分类可能仍显示未分类。两者不同是正常的：我们保存的是用户核对结果，没有改写 PayPal 原始数据。
4. 查看原币金额 USD 12、预算周期、限额和状态。已经确认的记录不必再“采纳一次”制造历史。
5. 再同步、重启后的检查见下面 C 部分。

### B. 使用干净源码和新的空数据库

1. 使用已获授权、已开通 Transaction Search 的同一沙箱账户配置启动。
2. 在“账本来源”查询 **2026-10-01 至 2026-11-30**；这是已实测覆盖目标购买的查询范围。历史实测返回四条活动，其中一笔购买可进入书页，三条按类型排除。以后账户新增活动时数量可能改变，不要硬凑四条。
3. 切换到对应的沙箱 USD 账本；用索引找到 USD 12 购买，并让阅读日期包含该记录的实际日期。
4. 检查或设置 **2026 年 11 月、USD 25 的月度总限额**，预览后保存。若已有相同限额，不必重复保存；不要因为只展示一天就把预算周期改成一天。
5. 打开“帮我弄清这笔”。测试购买的真实用途说明可填：

   > 这笔是沙箱测试购买的虚拟学习笔记本，用于整理课程笔记和学习资料；不涉及真实商品发货。

6. 检查发送预览，再调用真实模型。预期建议为教育并引用输入依据；如果模型给出不同建议、需要追问或失败，按实际结果核对，不要强行宣称成功。
7. 采纳教育分类后，若仍未确认认识消费，记录应继续待核对。接着由人勾选“我认识这笔消费”，检查其他待核对项，再点“保存核对，更新地图”。
8. 在数据覆盖和预算条件满足、没有其他提醒时，这笔可变为绿色。USD 13 的剩余额度只适用于已知总支出确为 USD 12、总限额 USD 25 的快照；如果数据不完整或又有支出，以界面实际解释为准。

### C. 再同步与重新打开，才算完成恢复核对

在同一副本中记录以下四项，再同步相同查询范围：

- 金额仍为 USD 12.00，没有重复导入第二笔；
- 人工分类仍为教育，PayPal 原始字段仍可追溯；
- 分类采纳与人工确认历史仍在，旧记录没有被同步覆盖；
- 月度预算、核对状态和 AI 采纳记录仍在。

然后关闭网页，在命令行 `Ctrl+C` 停止服务，再运行 `node server.mjs`，重新打开同一地址检查以上内容。完成了这些观察再说“恢复验证通过”。只刷新页面不能完全替代服务重启验证。

若要拍“从未核对到核对完成”的全过程，使用明确标注的练习副本，或者由负责人准备独立的干净测试副本。不要清空已经验收的主数据库，也不要把历史建议录成刚生成的模型回答。

## 8. 预算、阅读范围、查询范围不要混淆

| 概念 | 例子 | 会改变什么 |
| --- | --- | --- |
| 阅读范围 | 今天、这一周、某一类别 | 决定书里当前展示哪些记录 |
| 预算周期 | 2026 年 11 月整月 | 决定累计与限额如何比较 |
| PayPal 查询覆盖 | 已同步的起止日期与有效截止信息 | 决定有没有足够数据作预算判断 |

只看今天不会让月预算重新开始累计。数据覆盖不足时，不能把“没有看见其他支出”当成“没有其他支出”。金额等于限额不算超出；空值表示未设置，`0` 是真实的零额度。

USD 与 CNY 分开显示和计算，没有自动汇率换算。当前展示的总额是符合条件的已完成购买金额，**不是扣完退款后的净支出、账户余额或全部资金流水**。收款、转账、费用、退款活动等可能被排除，排除原因要能查看。

## 9. 常用操作与声音验收

| 想做什么 | 怎么做 |
| --- | --- |
| 翻开书 | 从封面点击开始；应看到书体打开，而不是直接跳到普通列表 |
| 翻页 | 书页边缘／页面按钮；也可尝试拖动书页 |
| 用键盘翻页 | 先让焦点进入书本区域，再按左右方向键；输入框、选择框或弹窗打开时不会拦截方向键翻书 |
| 快速找记录 | “账单索引”；无需把所有动画看完 |
| 只听状态 | 地图经过节点、靠近节点或图例试听；具体金额不应在浏览节点时自动报出 |
| 听具体消费 | 点击节点，展开“听一听这笔 · 设备朗读”，点击朗读；也可选择点开自动朗读 |
| 调整朗读 | “朗读设置”选择设备音色、语速并试听；可用音色由浏览器和系统决定 |
| 停止旧声音 | 停止朗读、关闭详情、翻页、静音或切换账本；实际听感仍需戴耳机验证 |
| 完全静音 | 使用应用静音；文字、颜色和形状仍应可理解 |

音效当前版本已得到项目负责人“可以区分、音量合适”的耳机反馈。这只是一人的反馈，不表示所有设备或所有人已经验收。

队友可以补做下面的真实听感核对，并记录设备、浏览器、结果，不要只写“都正常”：

- 闭眼试听三音型，能否稳定分清暖和弦、木敲与玻璃问句；是否刺耳或突然变响。
- 试听 USD 12、CNY 18／42／50／20 等现有记录，确认实际读出的币种、金额、原因与文字一致。
- 朗读到一半关闭详情，确认耳机中真的停止；再试静音、翻页和切换书。
- 连续接近不同节点，确认没有多种旧声音持续叠加；降低音量后仍能区分。
- 翻页、拖动后取消、重新开书是否保持合理阅读位置；小屏操作是否还能找到主要入口。

程序与浏览器状态测试已经覆盖一部分停止、静音和保存行为，但不能代替以上听音。若设备音色生硬，可换系统音色或以文字为主；不要说换模型就能改善设备朗读。

## 10. 录屏时怎么配合

建议两人分工：一人负责操作与数据状态，另一人负责英文旁白／字幕、计时、检查系统音频和记录问题。正式脚本采用本轮的 [中英文录屏材料](PITCH_RECORDING_KIT_ZH_EN.md)及 [英文字幕草稿](DEMO_SUBTITLES_EN.srt)，不要混用旧稿的时间线。

录制前完成：

1. 准备固定浏览器尺寸、同一地址和正确账本；关闭无关标签、通知、密钥文件与终端敏感输出。
2. 先录 10 秒样片，确认视频能同时录到应用声音和旁白；给三音型留安静空隙，不让背景音乐盖住差别。
3. 真实沙箱画面保留“Sandbox”来源说明。练习画面保留“示例／练习”说明，不能剪成真实消费。
4. AI 请求可能有等待或失败，事先熟悉操作，但不要把缓存标签藏起来冒充实时请求。
5. 对中文界面展示的关键操作、状态与结果提供完整英文旁白或字幕。仅最后放一句英文口号不够。
6. 实际导出视频控制在三分钟以内，并按正式规则核对；建议留出片头片尾和停顿余量。

最能说明价值的一幕是：**蓝色待核对 → 展示用途与 AI 引用 → 用户只采纳分类，仍为蓝色 → 用户独立确认 → 状态与书页更新。** 再用真实 Sandbox 来源及同步后历史仍保留说明数据链路。不要为了戏剧效果多付一次款。

配图需如实介绍：本版包含五张预先生成的 AI 主题插画，以及另有来源的真实素材。不是每翻一页在线生成图片，也不是团队亲自拍摄所有素材；详见 [素材来源](ASSET_SOURCES.md)。

## 12. 遇到问题先这样排查

| 现象 | 先检查 |
| --- | --- |
| `node` 找不到或 SQLite 相关报错 | 安装 Node.js 22.13+，重新开终端，检查 `node --version` |
| 4333 被占用 | 可能原项目仍在运行；先打开已有地址确认。不要再启动多份覆盖演示状态 |
| 改配置后没有变化 | 确认保存的是 `.env` 而非 `.env.txt`，停止并重启对应目录的服务 |
| 有书但没有真实 AI | 无 Key 时可以正常离线使用；检查模型配置与错误提示，不要把规则摘要当模型结果 |
| PayPal 认证成功，但同步 403 | 交易查询权限与 OAuth 分开；由账户负责人检查应用权限，不必重复购买 |
| PayPal 同步成功却看不到购买 | 检查账户、币种、查询范围、阅读范围、被排除事件与实际报告延迟；收款不等于购买支出 |
| 同一笔采纳教育后仍是蓝色 | 检查是否已独立确认认识消费、是否还有其他待核对项；这是可能的正确行为 |
| 没声音 | 先点击启用声音／试听，检查应用静音、系统音量和浏览器标签静音；设备朗读还需检查可用音色 |
| 重新打开状态变了 | 检查副本路径、账本来源、浏览器／端口是否改变；不要直接删数据库 |
| 要发报错给负责人 | 发不含密钥的错误码、操作步骤和界面；不要发 `.env` 内容或未经审查的完整日志 |
